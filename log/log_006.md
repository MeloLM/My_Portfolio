## 🅰️ Ciclo A — Audit della V1 e riscrittura completa in Tailwind

### A1. L'audit che ha originato tutto

Prima di scrivere codice è stato eseguito un audit completo della V1. Il codice risultava sano sul piano formale — `tsc --noEmit` a 0 errori, lint pulito, 22 test verdi, build a 15 pagine — ma sono emersi dodici difetti sostanziali, alcuni dei quali invisibili agli strumenti automatici.

**I due più gravi riguardavano le credenziali**:

```js
// src/constants/index.ts
serviceId:  process.env.REACT_APP_EMAILJS_SERVICE  || 'service_[REDACTED]',
templateId: process.env.REACT_APP_EMAILJS_TEMPLATE || 'template_[REDACTED]',
publicKey:  process.env.REACT_APP_EMAILJS_KEY      || '[REDACTED]',
```

Il prefisso `REACT_APP_` è un residuo di Create React App: in Next.js **solo `NEXT_PUBLIC_` raggiunge il bundle client**, quindi quelle tre variabili valevano sempre `undefined` e il form funzionava unicamente grazie ai fallback hardcodati e committati. `Feedback.js`, che quei fallback non li aveva, falliva in silenzio a ogni invio.

**Gli altri dieci**: blog buildato ma senza alcun link nella UI; sitemap con sole ancore e nessuna rotta dinamica; tre icone skill prese in prestito da altre tecnologie (Next.js col logo React, PostgreSQL con MySQL, Supabase con MongoDB); OG image quadrata 512×512 servita con `summary_large_image`; `banner-bg2.png` da 2,3 MB caricata come `background-image` CSS, quindi fuori dall'ottimizzatore; loading screen artificiale da 800 ms davanti all'LCP; migrazione TypeScript ferma a metà; `App.css` monolitico da 1595 righe accanto a una `styles/` modulare; file e dipendenze morte mai rimossi; documentazione che dichiarava feature inesistenti.

### A2. La riscrittura

Su richiesta è stata eseguita una riscrittura completa in quattro task, con `tsc --noEmit` come cancello fra l'uno e l'altro: salvataggio del debito tecnico in `TODO.md`, data layer tipizzato, setup Tailwind, costruzione della landing.

| Ambito | Intervento |
|---|---|
| Tema | Abbandonato il tema Dark Souls per un dark corporate stile AstroWind: Slate 950 `#020617`, Slate 50 `#f8fafc`, Blue 500 `#3b82f6`, font Inter |
| Styling | Tailwind 3.4 con token semantici in stile shadcn/ui; eliminati `App.css`, `index.css` e l'intera `src/styles/` |
| Data layer | `strict: true` attivato, 11 interfacce, array `readonly`, `skillsData` → `skills` con categorie, `imgAncor` → `url` + `linkType` |
| Icone | Regola codificata nel tipo: logo autentico **oppure** fallback `lucide-react`, mai riciclo |
| Sezioni | Hero, Skills a griglia Bento, Projects, Timeline verticale asimmetrica, Contact in stile dashboard |
| Immagini | Background da 2,3 MB sostituito da un gradiente CSS; screenshot da 2,59 MB convertito in WebP da 183 kB (−93%) |

**Risultati misurati**: file sotto `src/` da 83 a 39, zero `.js` residui, CSS scritto a mano da 3812 a 104 righe, `public/` da 8,61 MB a 1,9 MB, First Load JS della home da 132 kB a 118 kB, 8 dipendenze disinstallate.

Tutte le verifiche erano verdi, compreso uno smoke test HTTP sulla build di produzione reale.

### A3. Il cambio di piano

A lavoro concluso è emerso un malinteso sul target: **la V2 non doveva sovrascrivere questo repository**, ma diventare un progetto parallelo in un repository separato. Poiché nulla era stato committato — l'intero lavoro viveva nel working tree — è stato possibile annullare tutto senza toccare la storia di git.

## 🅱️ Ciclo B — Rollback totale e ripristino della V1

### B1. Ciò che il `git clean` avrebbe distrutto

`git clean -nd` eseguito **prima** del comando reale ha rivelato tre file non tracciati estranei alla V2, che sarebbero stati cancellati senza preavviso:

| File | Rischio |
|---|---|
| `ai_law.md` | Regolamento agente AI, file dell'utente del 21/08/2026 |
| `.env.backup-v1` | Dopo il `reset --hard` il `.gitignore` torna alla versione V1 (`.env`, `.env*.local`), che **non** copre questo nome: sarebbe sparita l'unica copia delle credenziali originali, prima ancora di poterle ripristinare |
| `public/fonts/` | Cartella vuota preesistente del 27/01/2026 |

Tutti e tre sono stati esclusi con `git clean -fd -e <pattern>`.

> ⚠️ È proprio la lettura di `ai_law.md`, salvato in extremis, ad aver rivelato l'esistenza di un regolamento di progetto che imponeva un log obbligatorio per ogni task — regola fino a quel momento mai applicata.

### B2. Backup preventivo fuori dal repository

Prima del reset, l'intero lavoro V2 è stato serializzato in un patch unico, binari inclusi:

```bash
git add -A -- . ':!ai_law.md'
git diff --cached --binary > <scratchpad>/portfolio-v2-completo.patch   # 9,5 MB
git reset -q
```

### B3. Esecuzione del rollback

| # | Operazione | Esito |
|---|---|---|
| 1 | `git reset --hard` | HEAD → `ac4c206`, 108 file tracciati riportati allo stato originale |
| 2 | `git clean -fd` con tre esclusioni | 17 elementi V2 rimossi |
| 3 | Ripristino `.env` da `.env.backup-v1` | Identico all'originale, verificato con `diff -q` |
| 4 | Rimozione di `.env.backup-v1` dalla root | Sotto il `.gitignore` V1 non sarebbe stato ignorato: un file di credenziali non ignorato non è "V1 intatta" |
| 5 | `npm ci` | `node_modules` riallineato al lockfile V1 |

### B4. `npm ci` rifiutato dal sistema operativo

Il primo tentativo è fallito:

```
npm error The operation was rejected by your operating system.
npm error It's possible that the file was already in use (by a text editor or antivirus)
```

**Causa reale**: due processi Node del server di produzione avviato per lo smoke test del ciclo A erano rimasti vivi (PID 30132 e 31344) e tenevano bloccati file dentro `node_modules`. La chiusura del task di shell aveva terminato il wrapper bash ma non i figli detached.

Terminati i processi e liberata la porta 3000, `npm ci` è andato a buon fine. Verificato a valle: 16 dipendenze di produzione e 12 di sviluppo, esattamente la V1; `bootstrap`, `react-bootstrap`, `react-multi-carousel`, `react-icons`, `prop-types` e `react-mailchimp-subscribe` presenti; `tailwindcss`, `lucide-react`, `clsx`, `tailwind-merge` e `@tailwindcss/typography` assenti.

### B5. La prova che il ripristino è esatto

`.next` è stata eliminata prima della build di verifica, per non riusare chunk della V2. Gli hash generati:

```
chunks/117-3627b6dd72c75653.js
chunks/fd9d1056-eafe4e40999011bd.js
```

sono **identici a quelli della build eseguita a inizio sessione** sulla V1 originale. L'output non è semplicemente funzionante: è uguale byte per byte. A conferma, `git diff --stat` non riporta alcun file tracciato modificato.

## 🅲 Ciclo C — Regolamento di progetto e sincronizzazione dell'archivio

### C1. Da `ai_law.md` a `ai_law_portfolio.md`

Il vecchio regolamento era generico e conteneva una sezione su "voti e locali" da isolare con feature flag, che **in questo repository non ha alcuna corrispondenza**: proveniva da un altro progetto.

È stato sostituito da `ai_law_portfolio.md`, specifico per il portfolio, con sette sezioni vincolanti:

| # | Regola | Sintesi |
|---|---|---|
| 1 | Gestione log | Cartella `log/`, nomenclatura `log_NNN.md`, struttura dei log storici |
| 2 | Sicurezza zero-trust | Nessuna credenziale in chiaro, nemmeno come fallback; solo `NEXT_PUBLIC_` |
| 3 | Qualità del codice | TypeScript strict, nessun `any` ingiustificato, zero `.js`/`.jsx` sotto `src/` |
| 4 | Blocco commit | Mai `commit`/`push` senza autorizzazione esplicita; esteso a `reset --hard`, `clean`, `rebase`, `push --force` |
| 5 | Verifica obbligatoria | `tsc --noEmit` e suite di test verdi, con output reale, prima di dichiarare concluso un task |
| 6 | Build e ambiente Node | Divieto di `build` con dev server attivo, notifica se resta un server acceso, cautela OneDrive |
| 7 | Lingua e comunicazione | Italiano nei log e nell'interfaccia, nessun dato inventato, numeri da comandi realmente eseguiti |

Le regole 6 e 7 conservano la sostanza utile del vecchio file (gestione build, lingua, divieto di dipendenze non richieste); la regola 4 è stata estesa a tutte le operazioni distruttive, non al solo commit, alla luce di quanto emerso nel ciclo B.

### C2. Unificazione dell'archivio log

La cartella storica si chiamava **`archivio log/`** — con uno spazio nel nome — mentre il nuovo regolamento prescrive `log/`. Lasciarle divergere avrebbe reso il regolamento falso dal primo giorno.

| Azione | Comando | Esito |
|---|---|---|
| Rinomina tracciata | `git mv "archivio log" log` | 5 log storici spostati, git li registra come `R` (rename), storia preservata |
| Nuovo log | `log/log_006.md` | Questo file, formattato secondo lo standard dei precedenti |
| Rimozione duplicato | `rm -rf logs/` | Cartella non standard creata per errore durante il ciclo B |

Il report intermedio `logs/report_2026-09-18_18-36-15.md` è stato riscritto in questo `log_006.md` e la cartella `logs/` eliminata.
